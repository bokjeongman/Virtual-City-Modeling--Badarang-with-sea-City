# 바다랑 🌊

**바다의 활기와 마을의 일상이 공존하는 도시**

바다랑은 해수욕장이 있는 바닷가 도시를 격자 지도로 만들고, 창고형 마트를 **해수욕장 근처에 둔 해변형 배치**와 **도시 입구 근처에 둔 입구형 배치**를 28일 동안 비교하는 Python/Tkinter 시뮬레이션입니다.

주말이면 관광객이 도시 입구로 들어와 바다를 보고, 창고형 마트에서 고기를 사서 숙소로 갑니다. 주민도 같은 마트에서 매일 저녁 장을 봅니다. 두 집단의 이동이 겹치는 곳에서 길이 막히고, 숙소 주변에는 소음이 생기며, 그 피해가 다음 날 주거지 인구 변화로 이어집니다.

혼잡을 도시의 어느 곳에서 감당하는 것이 관광과 주민 생활을 함께 지키는 데 유리한지 살펴보는 것이 목표입니다.

## 초기 상태

| 항목 | 설정 |
|---|---|
| 주거지 | 8칸(H1~H8), 모두 건물 1채와 주민 3명, 전체 인구 24명 |
| 창고형 마트 | 해변형 (10, 3)\~(11, 4), 입구형 (1, 3)\~(2, 4), 2×2칸 |
| 숙소 | L1 (6, 5), L2 (12, 5), 각각 수용 인원 10명 |
| 도로 | y=2의 x=0\~13(입구 포함), x=9의 y=3\~5, y=6의 x=5\~12, 총 25칸 |
| 지형 | y=7 해수욕장(해변), y=8\~9 바다, 도시 입구 (0, 2) |
| 시간 | 1일차 월요일 낮, 마트 방문객 0명, 혼잡·소음 없음 |

두 배치는 **마트만 옮기고** 도로, 주거지, 숙소, 초기 인구는 그대로 둡니다. 원래 마트가 있던 칸은 빈 땅으로 되돌립니다.

## 시뮬레이션 규칙

### 시간의 흐름

- 하루는 **낮**과 **저녁**으로 나뉘고, 일주일은 평일 5일과 주말 2일입니다.

| 전환 | 처리 |
|---|---|
| 낮 → 저녁 | 지도를 고정하고 주민·관광객 이동을 계산한 뒤 방문객, 혼잡, 소음을 판정 |
| 저녁 → 낮 | 전날 저녁 결과로 인구와 건물을 한 번 갱신하고 기록을 남긴 뒤 일차 +1 |
| 낮 동안 | 현재 방문객과 혼잡은 0으로 표시 |

### 주민 장보기

- 도로로 연결된 주거지의 주민은 매일 저녁 BFS 최단 경로로 마트까지 이동합니다.
- 주거지마다 마트까지 이동 횟수를 구합니다.

### 관광객 동선

| 요일 | 동선 | 인원 |
|---|---|---|
| 토요일 | 입구 (0, 2) → 해수욕장 → 마트 → 숙소 | 20명 (L1·L2에 10명씩) |
| 일요일 | 숙소 → 입구 | 토요일 숙박객 |

- 관광객은 바다를 보러 오므로 마트 위치와 관계없이 **주말 20명으로 일정**합니다.
- 경로 구간은 BFS로 구한 뒤 `join_paths`로 이어 붙이며, 이음매 칸은 한 번만 셉니다.

### 도로 혼잡

- 주민과 관광객이 지나간 경로를 도로 칸마다 합산합니다.
- 통행량은 칸을 **지나간 횟수**로 셉니다. 왕복하면 왕복한 만큼 셉니다.
- 그날 저녁 통행량이 **12 이상**인 칸을 혼잡 도로로 판단하고, 그 칸에 **맞닿은 주거지**는 혼잡에 노출됩니다.

### 숙소 소음

- 토요일 저녁, 숙소와 **맨해튼 거리 2 이하**인 주거지는 소음에 노출됩니다.

### 주거 성장과 쇠퇴 (다음 날 낮)

| 전날 저녁의 조건 | 다음 날 주거 상태 |
|---|---|
| 마트 이동 10회 이내, 혼잡·소음 없음 | 주민 1명 증가 (최대 10명) |
| 같은 조건을 만족하는 빈 주거지 | 건물 1채 재건축, 주민 1명 입주 |
| 마트 이동 10회 초과, 혼잡·소음 없음 | 인구 유지, 빈 주거지는 입주 없음 |
| 혼잡 또는 소음에 노출 | 주민 1명 감소 (둘이 겹쳐도 1명만 감소) |
| 도로와 연결되지 않음 | 주민 1명 감소 |
| 주민이 0명이 됨 | 건물 철거, 주거 용도지역은 유지 |

## 첫날 결과

| 배치 | 혼잡 구간 | 피해 주거지 | 다음 날 인구 |
|---|---|---|---|
| 해변형 | (6, 2)~(9, 2), (9, 3) | H3, H6 | **28명** |
| 입구형 | (2, 2)~(6, 2) | H1, H2, H3, H5, H6 | **19명** |

관광객이 없는 평일에도 입구형은 주민의 장보기 경로가 입구 쪽에 몰려 해변형보다 불리합니다.
**관광객 교통을 바깥으로 밀어내는 배치가 항상 유리하지는 않습니다.**

## 비교 실험

- 각 배치를 1일차 월요일 낮, 인구 24명으로 초기화하고 28번의 낮 갱신까지 진행합니다.
- 비교 지표
  - 마트 방문객 수 (주민·관광객)
  - 혼잡 도로 칸 수
  - 피해 주거지 수 (건물 유무와 관계없이 주거 용도지역 8칸 기준)
  - 마지막 날 전체 인구

## 검증 방법

**시간 검증**
- 낮에는 방문객과 현재 혼잡이 0이어야 합니다.
- 저녁으로 바뀔 때는 인구가 유지되고, 다음 날 낮에만 한 번 변해야 합니다.
- 관광객은 주말에만 나타나야 하며, 화면을 반복해서 갱신해도 결과는 같아야 합니다.

**규칙 검증**
- 첫날 결과(해변형 28명, 입구형 19명)와 일치하는지 확인합니다.
- 도로를 끊었을 때 해당 주거지가 쇠퇴하는지 확인합니다.
- 마트와 직선거리가 가까워도 도로를 따라 이동하는지 확인합니다.
- 주거지 한 칸의 인구가 0~10명을 유지하는지 확인합니다.
- 마트 위치를 바꿔도 주말 관광객이 20명으로 일정한지 확인합니다.

## 주요 함수

| 함수 | 역할 |
|---|---|
| `tourist_path(city, lodging)` | 입구 → 해수욕장 → 마트 → 숙소 관광객 경로 생성 |
| `join_paths` | 경로 구간을 이음매 칸 중복 없이 연결 |
| `run_shopping` | 저녁 이동을 계산하고 `city["evening"]`에 결과 저장 |
| `advance_day` | 낮 ↔ 저녁 전환, 저녁 → 낮에 인구 갱신 |

`city["evening"]`에 저장되는 값:

| 키 | 내용 |
|---|---|
| `traffic` | 칸별 통행 횟수 |
| `tourist_visitors` | 관광객 방문객 |
| `congested_roads` | 혼잡 도로 |
| `congested_homes` | 혼잡 피해 주거지 |
| `noisy_homes` | 소음 피해 주거지 |

## 남은 과제

- 숙소 배정: 관광객 20명을 숙소 2곳(각 10명)에 나누는 규칙 정리
- 마트 입구가 여러 칸이라 같은 거리의 경로가 생길 때 방향 선택 기준 설명
- 요약 줄에 관광객 방문객 수·혼잡 도로 수 표시
- 계획서의 통행량 정의를 "인원"에서 "횟수"로 수정
